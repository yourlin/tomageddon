# 关卡场地设计方案（草案）

> 状态：设计已确认，按第 6 节顺序实现。与 `BOSS_PHASES.md` 一起在 0.7.0 实现（Boss 转阶段会改变场地）。

## 1. 现状与问题

- 所有章节共用同一块 **1920 × 1200 的矩形**场地（`BALANCE.arena`），镜头跟随玩家；场地画面是 1300 × 850 的程序化贴图拉伸而成。
- 第 1 章作为新手关，地图太大：怪刷在远处、要跑很远才捡得到番茄籽，节奏松散。
- 场地形状和章节主题无关：厨房、冰箱、城市垃圾场、工厂摸起来都一样，只有地面贴图和地形机关不同。
- 代码里有十几处直接用矩形边界做夹取（玩家移动、刷怪点、技能落点、地雷、Boss 传送等），不支持其他形状。

## 2. 目标

1. 每章场地的**大小**和**形状**跟着章节主题走，难度节奏也随之变化（小场地紧凑、大场地开阔）。
2. 支持 Boss 转阶段时**改变场地**：淹没一半、向内缩小、长出障碍。
3. 所有用到边界的地方改为统一的场地接口，以后加新形状不用再到处改代码。

## 3. 场地系统（框架）

### 3.1 形状

| 形状 | 说明 |
|---|---|
| `rect` | 矩形（可指定任意宽高） |
| `roundRect` | 圆角矩形 |
| `ellipse` | 椭圆 / 圆形 |
| `polygon` | 任意凸多边形（八边形、六边形、L 形用两个矩形拼） |
| `union` | 多块形状拼接（十字形、L 形、两个房间加一条走廊） |

另外可以放**障碍物**（圆形或矩形，比如柱子、冰柜、货架）。障碍物**只挡移动**：玩家和怪物不能穿过，所有子弹（玩家和怪物的）都直接飞过去。

### 3.2 统一接口

```ts
interface Arena {
  bounds: Rectangle;                                // 外接矩形：镜头边界、刷怪范围
  contains(x: number, y: number, pad?: number): boolean;
  clamp(x: number, y: number, pad?: number): { x: number; y: number }; // 推回场地内（也处理障碍物）
  randomPoint(pad?: number): { x: number; y: number };                 // 场内随机点（地形、坠物）
  edgeSpawn(awayFrom: { x: number; y: number }): { x: number; y: number }; // 刷怪点：沿边缘、离玩家够远
  blocked(x: number, y: number, r: number): boolean;                    // 是否撞到障碍物
  setRegion(change: ArenaChange): void;                                 // 运行中改变（Boss 转阶段用）
}
```

- 现有的 `Phaser.Math.Clamp(x, arena.x + 20, arena.right - 20)` 全部换成 `arena.clamp`，包括玩家移动、刷怪、技能落点、地雷、Boss 传送、宠物、分身。
- **子弹**：障碍物不挡任何子弹（玩家与怪物都一样），子弹只在飞出场地外接范围后消失。以后如果要做掩体，可以给障碍物加「挡怪物子弹」开关（见第 7 节）。
- **怪物移动**：撞到障碍物沿切线滑开（简单避障，不做寻路）；障碍物不会堵死刷怪口。

### 3.3 画面

- 场地内铺地面贴图，形状外画成该章的「墙 / 边缘」：厨房的橱柜、冰箱内壁、城市围栏、工厂铁栏等，沿形状边缘描一圈厚边。
- 场地贴图改为按实际大小生成，不再统一拉伸 1300 × 850，避免小场地被拉糊、大场地被压扁。
- 障碍物用程序化贴图画，风格和该章场景一致。

### 3.4 镜头

- 镜头边界取场地外接矩形加一圈边缘，场地小于屏幕的方向直接居中、不跟随。
- 每章可以设一个默认缩放：小场地正常缩放，大场地略微拉远（最多 ×0.9），让玩家看到更多场地。
- Boss 转阶段的运镜（见 `BOSS_PHASES.md` 2.5.1）在这个基础上做。

### 3.5 运行中改变场地

Boss 转阶段可以触发以下 4 种变化，变化前都有 1.5 秒预警，比如边缘闪红、地面出现预警条纹：

| 变化 | 说明 | 用在 |
|---|---|---|
| `shrink` | 场地按比例向中心收缩，收缩区域变成伤害地面 | 腐烂之王终焉阶段（缩到 70%） |
| `flood` | 指定区域暂时变成不可站立或持续伤害，到时恢复 | 番茄酱海怪酱潮（半场 4 秒） |
| `obstacle` | 场内长出或移除障碍物 | 枯萎园丁藤鞭、冰淇淋暴君掉落的冰淇淋球 |
| `split` | 用一道墙把场地临时切成两半 | 备用，暂不使用 |

## 4. 各章场地

### 4.1 设计思路：每张地图都是一件「放大的物件」

主角都是巴掌大的蔬果，所以场地不画成一块普通地板，而是厨房、菜园、工厂里的**某一件具体物件**。物件本身的形状就是场地形状，它的表面就是地面纹理，它的边缘就是墙：

- **一眼认得出**：进关就知道自己站在平底锅里、冰箱隔板上。
- **形状有来由**：平底锅是圆的、冰箱是竖长的、生产线是横长的，不用为了变化而硬凑形状。
- **机关有来由**：平底锅里的热油、冰箱里的冷风、生产线上的传送带，现有地形机关都能和物件对上。

尺寸单位是游戏逻辑像素（现在场地是 1920 × 1200，屏幕约 1280 × 720）。

### 4.2 各章方案

| 章节 | 地图（物件） | 形状 | 尺寸 | 地面纹理 | 边缘（墙） | 障碍物 | 地形机关的对应 |
|---|---|---|---|---|---|---|---|

| 2 · 荒芜菜园 | **一块菜畦** | 圆角矩形 | 1760 × 1100 | 深褐色泥土，横向一垄一垄的田垄纹，夹杂枯叶和石子 | 木栅栏围一圈 | 2 个稻草人、几处兔子洞土堆（圆形） | 兔子洞、土拨鼠洞、洒水器原样保留，位置贴着田垄 |

### 4.3 要点说明

- **第 1 章平底锅**：圆形没有角落可以卡怪，适合新手；中心发红的光晕暗示「越往中心越烫」，以后可以做成中心区域热油更多的机关。面积和之前提的 1440 × 900 差不多，节奏同样紧凑。
- **第 7 章腐烂番茄**：最终章站在「腐烂的源头」本身里面。腐烂之王终焉阶段的缩场（见 `BOSS_PHASES.md`），表现为果肉从外圈开始腐烂塌陷，和场地主题一致。
- **章节名**：第 1 章改名为「第一章 · 平底锅」。
- **画面实现**：每张地图的纹理都是程序化绘制（和现在的场地贴图一样），不需要外部美术资源。边缘画成有厚度的立体边，让玩家看清可走范围。

## 5. 对玩法与平衡的影响

| 方面 | 影响 | 处理 |
|---|---|---|
| 难度 | 场地越小越难躲，怪也更快贴脸；越大越容易风筝 | 每章改完单独测通关率，用刷怪密度和章节生命微调回目标区间 |
| 刷怪 | 小场地刷怪点离玩家近，怪会扎堆 | 刷怪点改为「沿边缘、离玩家至少 450」，场地太小时降低每批数量 |
| 地形机关 | 现在的机关位置按矩形随机，可能落在障碍物里或场地外 | 改用 `arena.randomPoint()`，并避开障碍物 |
| 技能与武器 | 冲刺、传送类技能、地雷落点可能落进障碍物 | 统一用 `arena.clamp` 推出障碍物；子弹、回旋镖、火焰都不受障碍物影响 |
| 测试 bot | 现在按矩形中心（960, 600）和固定边界走位 | 改为读取场地接口，避障和远离边缘都用 `arena.contains` |
| 性能 | 障碍物碰撞多一层判断 | 每章障碍物 ≤ 6 个，用简单圆形 / 矩形检测，开销可以忽略 |

## 6. 实现计划

1. **场地接口与矩形实现**：先把十几处直接夹取边界的代码换成统一接口，行为保持不变（依然是 1920 × 1200）。跑一遍测试确认没有回归。约半天。
2. **形状与障碍物**：圆角矩形、椭圆、多边形、拼接，加障碍物碰撞（玩家、怪物；子弹不受影响）、怪物沿障碍滑开。约 1 天。
3. **画面**：按形状生成场地贴图，每章的边缘与障碍物画法，镜头边界与居中。约 1 天。
4. **各章配置**：7 章的形状、尺寸、障碍物，地形机关改用场地接口。约半天。
5. **运行中改变场地**：`shrink` / `flood` / `obstacle` 三种变化与预警表现，供 Boss 转阶段使用。约半天。
6. **测试 bot 与平衡**：bot 读取场地接口；全角色 7 章测试，逐章回调到目标区间。约 1 天（多数是等测试跑完）。
