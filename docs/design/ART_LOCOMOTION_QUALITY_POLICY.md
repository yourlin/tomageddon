# 移动动画方向与验收

用户确认：所有走路、奔跑和冲刺的原始连续帧统一朝右；向左只由程序水平镜像整张贴图。此要求适用于默认角色、皮肤、Boss、精英和小怪的后续制作及已有问题修复。

- 同一动作的所有帧保持身体、头部、腿和脚尖朝右。不能在序列中混入朝左帧，不能只镜像腿、手或局部衣物来凑另一侧姿势。
- 每帧放大核对后脚的脚尖、脚跟和踝关节；后腿向左伸展时，不能把后脚误画成朝左。整个人物缩略图朝右不足以证明脚部方向正确。
- 行走按右向步态绘制：左右腿交替向右迈出和承重，后腿可以在身体左侧，但脚尖仍朝右；手臂与腿反向摆动。不能用面向镜头踢腿代替右向行走。
- 冲刺保持右向前倾、蹬地、腾空与收势的动作连续性。腿可以向后伸展，但不能反转脚部解剖方向或切换身体朝向。
- 披风、围巾、蝴蝶结等固定在同一身体侧，随动作自然摆动；左向显示时与整张贴图一起镜像。
- 无腿对象按真实结构制作右向滑行、爬行或飞行，不补虚构的双腿步态。
- 所有源帧具有一致的镜头、比例和接地基准。位移由游戏负责，序列本身不能逐帧漂移。

程序根据主动移动速度或锁定的冲刺速度决定左右方向。纯竖直移动保留上一水平朝向；静止怪物可以转向目标。击退不算主动行走。默认源朝向为 `facing: 1`，朝左使用整张图的 `flipX`，不另加载一套左向资源。

验收必须同时具备：逐帧接触表人工检查、正常速度循环播放、慢速播放、游戏内左右移动和冲刺验证。帧数、切图、眨眼时长和显存释放检查不能代替动作方向验收。旧的“接入/基础验证通过”记录仍保留，但不代表本项已通过。

当前复查记录：`reports/art-pilot/direction-audit/index.json`。程序朝向专项验证：`reports/art-pilot/direction-audit/runtime-facing.json`。全量视觉复查完成前不得宣称所有动作方向已修复。

当整张四帧生图反复重复同一领步腿时，改为逐张生成关键帧，再组装图集：近侧腿接触、承重/经过、远侧腿接触、相反承重/经过。每张必须有真实关节姿态变化与前后遮挡关系，不能只靠调色交换腿的身份。统一全画布缩放用于排版可以接受，不能用缩放制造动作。单帧原画、提示词、被拒版本和组装清单均留仓库外。生姜实例见原画目录 `drafts/char/ginger/rightward-single-frames/assembly.json`。

## 双手前后与肢体连接专项校验

用户追加要求：每张图必须校验左右手的前后位置；错误的整帧重新生成，不能以基础程序检查通过放行。

- 使用角色自身的近侧/远侧肢体身份，不以画面左/右位置代替。每帧追踪肩部连接点、上臂、肘、前臂、腕与手，不能在摆臂换相时换肩、换手身份或从错误一侧长出。
- 右向三分之四视图中，近侧手臂前摆必须从可见近侧肩部连贯地跨过身体前景；远侧手臂后摆应被躯干遮挡，不能作为一只完整近侧手贴在前景。后摆时仍保留同一近侧肩部连接。
- 近远侧肩部身份与遮挡逻辑沿序列必须一致：远侧手臂后摆时应被躯干遮挡，近侧前摆臂在躯干前。双手前伸、护脸或施放技能时，远侧前臂和手可以自然绕到身体前方，但必须能追溯到同一个远侧肩部，不能换肩或穿过躯干。不能只移动拳头、更换大小或用局部镜像掩盖错误连接。
- 同时核对手脚数量、分离、肘腕/膝踝朝向、相反摆臂和交替承重；手脚融合、手变成脚、踢腿代替走路都拒用。
- 每套全部动作逐帧检查，并正常及慢速连续播放；疑似或无法确认的帧不算通过，重新生成并复查。已接入和基础通过的资源同样需要本专项复查。
- `limbOcclusionVerified` 在取得实际视觉证据前保持 false；代码、帧数、截图存在和普通运行检查均不能将其置为 true。

## 透明边缘的实际合成检查

- 判断光晕、杂边、漂浮碎片前，先按源 PNG 的 alpha 通道分别合成到灰底、白底和深色底，查看实际可见结果。原画及 alpha 保持原样；合成图仅作为仓库外 QA 证据。
- alpha 为 0 的像素即使保留彩色 RGB，也不可据此认定游戏里存在光晕或要求重绘。预览器可能显示这些隐藏颜色，须用实际 alpha 合成结果复核。
- 半透明或不透明的错误边缘仍需修复，不能清除源 alpha、阈值抠图或局部修肢来掩盖问题。透明边缘合格也不能代替肢体、步态和连续播放验收。
